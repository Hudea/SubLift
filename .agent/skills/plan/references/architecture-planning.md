# Architecture Planning 方法

仅在 `plan_type: architecture` 时读取。

## 输入前提

- 有明确问题、影响范围与约束。
- 至少有一个架构决策问题。
- 目标不是单纯文件级实现清单（否则 `ROUTE_MISMATCH`）。

## 调查顺序

1. `docs/ARCHITECTURE.md`、相关 `docs/design/*`、`docs/DECISIONS.md`。
2. 入口、依赖方向、数据流、测试边界。
3. 区分不变量、硬限制与可调整部分。
4. 2～3 个实质不同候选；仅一案时说明排除其它的证据。
5. 比较边界、耦合、兼容、迁移、可测性、风险、回滚。
6. 推荐方案、否决理由、D3 项。
7. 目标边界、接口/数据契约、迁移顺序、回滚、后续 Feature 约束。
8. 成功判据（结论成立条件）与验证方案（如何检查）分开写。

## 输出

- 结构用 `../assets/architecture-plan.md`。
- 引用具体文档/模块/代码路径。
- 写职责与契约，不展开完整函数级任务。
- 未定内容放开放问题，不伪装已决。
- Gate 对照模板末节与 planning rule。
