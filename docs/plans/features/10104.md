# 10104 搭建 Native Workspace Shell — 执行计划

> 状态：in-progress（2026-08-12 启动）。计划正文；验收证据写入 `docs/phases/phase10.json` 的 10104.evidence。

## 目标

建立系统 Toolbar、Video/Transcript Split、统一 Menu Commands 和 960×600 响应式基础，先复用现有业务 View（VideoPreview/VideoControlsView/SubtitleList/metadataBar/extractionBar/RegionCandidateList）。

## 验收标准（来自 phase10.json）

1. Ready 主窗口 Video 60–65% / Transcript 35–40% 可调 Split；1280×800 与 960×600 无主动作裁切。
2. Toolbar 只放 Open、文件上下文、Region、Extract/Stop/Export 与 Inspector；engine/quality 不常驻。
3. File/Edit/Playback/View 菜单与 Toolbar 共用 Workspace commands，按状态启用；Space 播放/暂停。
4. 窗口变窄先回收 Inspector 预留位、Transcript 缩至 ≥约 320pt；不退回 800×480 全塞布局。
5. layout/command tests、swift test、V03 与 V08 实际截图写入 evidence。

## 测试先行顺序（TDD）

1. `WorkspaceLayoutTests`：
   - 1280（无 Inspector）→ video ∈ [60%, 65%]
   - 960（无 Inspector）→ video ∈ [60%, 65%] 且 transcript ≥ 320
   - 960 + Inspector 300 → transcript 保持 ≥320（Inspector 预留先回收）
   - 极窄（如 700）→ transcript ≥ 320、不崩溃
   - 比例单调：container 增大 → video/transcript 单调不减
2. 实现 WorkspaceLayout 通过。
3. UI/命令实现后：完整 swift test。

## 状态与数据所有权

- WorkspaceModel 仍是导入/命令 availability 真源；菜单、Toolbar 只绑定其 action 与 commandAvailability。
- WorkspaceLayout 是纯函数（无状态），View 用它指导 Split 初始比例与最小宽度；HSplitView 允许用户调整。
- 菜单 Space 与 Toolbar/按钮共用 playerModel.togglePlay（单一 action）。

## UI 与 Core 职责边界

- Core：WorkspaceLayout 计算、WorkspaceModel 命令。
- UI：Toolbar 布局、菜单声明、Split 组装；View 不实现业务逻辑。
