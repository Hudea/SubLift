# 08205 实现可靠的串行队列调度器 — 执行计划

> 状态：in-progress（2026-08-12 启动）。验收证据写入 `docs/phases/phase8.json` 的 08205.evidence。

## 调度不变量（冻结）

### Ports（依赖注入）

- `BatchTaskRunning`：Runner port。`run(_ task:, onUpdate: @escaping (BatchTaskStatus, Double?) -> Void) async -> BatchRunOutcome`（completed(entryCount:outputURL:)/failed(String)/cancelled）。Scheduler 唯一运行依赖；不解析 IPC、不碰文件系统。
- `BatchQueuePersisting`：Repository port。`load() throws -> BatchQueueState` / `save(_:) throws`。08205 仅定义协议（08207 实现 JSON 持久化；测试用内存假实现）。

### BatchQueueScheduler（@MainActor）

- `maxActive = 1`：任意时刻最多一个 preparing/extracting/exporting；前项 teardown 完成后才启动下一项（Fake Runner maxActive 记录证明）。
- 每个任务启动冻结 run token；迟到 progress/final/error 回调被拒绝（token 校验 + 状态机双重）。
- `stop()`：当前任务取消（runner 感知取消返回 .cancelled；token 保持有效直到 runner 返回，
  结果接受为 cancelled）+ 不再调度；等待项保持原顺序。
- `pauseAfterCurrent()`：当前任务完成后进入 paused（不启动下一项）；`resume()` 恢复。
- `cancel(taskID)`：waiting → cancelled；运行中 → 立即标记 cancelled（状态机拒绝后续迟到回调）
  + runner 取消；调度继续。
- `onUpdate` 仅接受活动态（preparing/extracting/exporting）；progress 与状态转换解耦
  （同阶段多次进度上报保留）；终态只走 outcome 通道。
- 单任务 failed → 继续下一项；`retry(taskID)`：failed/cancelled/interrupted → waiting（requeue
  绕过状态机终态限制，方法内守卫）；completed 不可重跑。
- `remove/reorder/replaceConfiguration` 仅 waiting 可执行；运行/终态非法命令由 `BatchTaskCommandAvailability` 唯一真源拒绝。

### BatchTaskCommandAvailability（唯一真源）

```swift
isActive = preparing/extracting/exporting
canRemove = waiting
canReorder = waiting
canReplaceConfiguration = waiting
canCancel = waiting || isActive
canRetry = failed/cancelled/interrupted
```
