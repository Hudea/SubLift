# 10103 实现 Welcome 与视频导入状态 — 执行计划

> 状态：in-progress（2026-08-11 启动）。计划正文；验收证据写入 `docs/phases/phase10.json` 的 10103.evidence。

## 目标

以 WorkspaceModel 为真源实现 empty 工作区、Open、合法/非法拖拽、加载反馈和新视频切换；不改变现有容器/ffmpeg 支持边界。

## 验收标准（来自 phase10.json）

1. empty 按 V01 展示单一 Open 主动作、本机处理说明与 MP4/MOV/MKV 支持，不使用整窗 Card/渐变/永久虚线框。
2. 合法拖入按 V02 显示 Accent 边界、动作文字和 VoiceOver 状态；非法类型被拒绝并给出非纯颜色反馈。
3. Open Panel 与 drop 走同一导入 intent；新视频正确重置 metadata/region/transcript/selection/error，Settings 不受影响。
4. MKV/ffmpeg 缺失继续 fail with actionable alert，不把安装命令作为唯一主文案，也不静默换容器。
5. 导入状态单测、swift test、V01/V02 实际截图与 accessibility label 清单写入 evidence。

## 测试先行顺序（TDD）

1. `VideoImportPolicyTests`：格式白名单（mp4/mov/mkv，大小写）、非法格式、MKV 依赖 ffmpeg、UTType 非空。
2. `WorkspaceImportTests`：openVideo fail-closed（非法格式/MKV 无 ffmpeg 时 Session 不变）、合法格式进入 loading、validateImport 与 openVideo 门一致、新视频清理 region/selection/error、Settings 不受影响。
3. 实现后专项测试通过 → 完整 `swift test`。

## 状态与数据所有权

- WorkspaceModel 拥有导入 intent（`openVideo`）与校验真源（`validateImport`）；drop 与 Open Panel 都汇聚到同一函数。
- `dragActive` 是 View 层瞬时状态（SwiftUI `isTargeted`），不进入 10102 已冻结的 10 态 `WorkspaceState`；命令矩阵不受拖拽影响。
- View 只投影状态、发送 intent、呈现反馈（Accent 边界、动作文字、错误 inline）。

## UI 与 Core 职责边界

- Core（VideoImportPolicy / WorkspaceModel）：格式判断、ffmpeg 依赖、Session 变更门（fail-closed）。
- UI：Open Panel、drop 反馈视觉、alert 呈现、错误文案。View 不实现格式判断或 runtime fallback。

## Computer Use 验收场景

- V01：empty，1280×800，Light — Welcome 层级、单一 Open 主动作、无整窗 Card/永久虚线框。
- V02：dragActive，Light — Accent 边界、动作文字、VoiceOver 状态（真实拖拽悬停或程序化悬停）。
- 非法拖入（.txt）：inline 图标+文字反馈，Session 不变。
- 合法 drop（MP4）：loading → ready；Open Panel 同路径。
- MKV 导入：本机 ffmpeg 存在 → 正常导入；无 ffmpeg 的 alert 场景由单测覆盖，UI 演示视本机状态如实记录。
- 切换视频：重置 region/transcript/selection/error。
