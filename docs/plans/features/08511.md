### 文件夹归属

```swift
struct BatchAcceptedItem { let url: URL; let importRootURL: URL? }
// 目录扫描 → importRoot = 该目录；直接文件 → nil
```

`BatchTask.importRootURL: URL?` 加法 Codable：`decodeIfPresent`，旧清单缺键 → nil。不 bump schema。

**PR1 必须改 `BatchQueueModel.importInputs`**：`BatchTask.make(..., importRootURL: item.importRootURL)`。只加 `acceptedURLs` 而不改 Model 会让位置列永远走 parent。本 PR 不规划输出。

位置列（文件与状态之间）。比较用 `standardizedFileURL`。源不在 import root 下 → 回退 parent 规则。

| 条件 | 显示 |
|---|---|

| 无 root 或源已脱离 root | parent `lastPathComponent` |

`visibleColumns(forWidth:)`：`<960` 文件/状态/进度；`≥960` +输出；`≥1100` +位置；`≥1280` +引擎/时长/添加时间。GeometryReader + 四档 Table 变体，不用 `TableColumn.hidden`。位置不可见时折进文件单元格。

### Inspector

`TaskInspectorModel` 驱动一张卡片：

```
filename + 状态          删除 / 上移 / 下移
位置 · 在 Finder 中显示
输出  字幕将保存到：<folder> / <name>.srt
      该字幕已存在，开始时将确认是否替换   // outputFileExists 必显
      planningError                        // 预览失败，不进「错误」行
提取  引擎 [popup]  质量 [popup]     // labelsHidden；只读则纯文本
错误 / 操作（取消|重试）按 availability
```

产品 UI 无 Task ID。去掉重复「配置」行。卡片上限 240pt + 内滚。

`planningError` **不是** `BatchTask` 字段。Model 持有瞬时 `@Published planningErrors: [UUID: String]`，不进 JSON；每次 `planOutputsForWaitingTasks` / `prepareOutputPlan` 整表替换。工厂：`inspectorModel(for:fileExists:planningError:)`，第三参来自该字典。禁止塞进 `failureMessage`。

### 导出

**现状（写进 UI 文案）：** 文件导入与文件夹导入都是 sidecar。非递归时 sidecar 正好在所选文件夹。

**默认保持 sidecar（用户已确认 Q1=Yes）。** 导入后立刻 `previewTarget`，waiting 任务写入 `outputURL`，输出列不再是「—」。已存在目标：仍 waiting，**必显**「该字幕已存在…」，开始时再确认替换。**禁止导入期 skip**（今日 `prepareOutputPlan` 也不标 skipped，不要「修」成 skipped）。

导入预览与开始 `plan()` **共用** `sourceRootForPlanning(task) == task.importRootURL`。禁止 `prepareOutputPlan` 再写死 `sourceRoot: nil`。

`cancelStart` 只清 `pendingConflicts`，**保留**预览 `outputURL`。改写 `testCancelStartDoesNotTouchOutputs`。

开始路径 `unwritableDirectory` / `targetOutsideRoot` / 同批碰撞：不启动、alert、任务保持 waiting。同批公共根碰撞：先到先得，后者 `planningError`。

`retry` / `setOutputDestination` 后必须重算预览（waiting + retryable）。今日 `setOutputURL` 只允许 waiting（`BatchQueueScheduler.swift:174–181`）——**PR2 必须放宽**为 `status == .waiting || canRetry(status)`，且只改 `outputURL`。RED：fail → 切公共根 → **retry 前** `outputURL` 已在新根、status 仍 failed。

同批碰撞：前者有 `outputURL`；后者 `planningErrors[id]` 有文案、`outputURL == nil`、Inspector「错误」行仍空。

`BatchOutputPlanner.previewTarget`：纯路径 + 公共根逃逸检查；不查可写、不读冲突、不写文件。

相对路径：`BatchPath.relativePath` 用 `hasPrefix(root + "/")` + `dropFirst` + trim 前导 `/`。**不要**复用 Scanner 现有弱 `hasPrefix(rootPath)`。反例：`/data/v`+`/data/v/show/data/v` → `show/data/v`；`/data/video` 不是 `/data/video2` 的前缀。

**Destination 持久化（PR2 基础设施；用户已确认 Q2=Yes，PR5 接线菜单）：**

```
save:  Snapshot(..., outputDestination: state.outputDestination)   // 必传
load:  State(..., outputDestination: snapshot.outputDestination ?? .sidecar)
Scheduler.setOutputDestination → persist()
```

Model 不得另持一份 destination。`BatchOutputDestination` 显式 `{ "type": "sidecar" } | { "type": "publicRoot", "url": ... }`。State 自定义 `decodeIfPresent`。往返测必须 `repository.save` → 新 repo `load()`。

PR5 接线 Toolbar「输出位置」（用户已确认 Q2=Yes）。无逐任务自定义路径。
