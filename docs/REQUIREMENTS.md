# SubLift 需求规格

## 1. 项目目标

为桌面用户提供一个**本地、离线、免费**的硬字幕提取工具，把烧录在视频画面中的字幕还原为可编辑的字幕文件。当前阶段聚焦 Apple Silicon Mac，长期目标是跨平台。

## 2. 用户与使用场景

| 用户类型 | 典型场景 |
|---|---|
| 字幕组 / 翻译者 | 二次校对、翻译已烧录字幕的影视片段 |
| 内容创作者 | 把旧素材中的硬字幕重新结构化，便于再剪辑 |
| 学习者 | 从带字幕的教程视频中导出文本，便于检索与笔记 |
| 开发者 / 技术用户 | 通过 CLI 批量处理视频文件 |

## 3. 功能需求

### 3.1 必需功能（MVP）

- **F1 视频输入** ✅：支持主流容器与编码（mp4 / mkv / mov，H.264 / H.265）。
- **F2 帧采样** ✅：按可配置的采样率（默认 1 fps）从视频中抽取关键帧。
- **F3 字幕区域检测** ✅：默认裁剪画面下部 30%，支持手动指定区域；Apple Vision 自适应定位。
- **F4 OCR 识别（多引擎可路由）** ✅：通过统一接口调用 OCR 引擎，引擎可热插拔；已集成 Vision 和 PaddleOCR 两种引擎，返回文本 + 置信度。
- **F5 时间轴生成** ✅：基于变化点检测状态机生成 `start_ms` / `end_ms`，不再使用固定占位逻辑。
- **F6 去重与合并** ✅：合并连续相同/相似的识别结果，消除抖动。
- **F7 字幕导出** ✅：支持 SRT、ASS、VTT 三种格式。
- **F8 CLI** ✅：`sublift extract <video> -o <output>`，支持参数覆盖默认配置，包括手动指定 OCR 引擎。

### 3.2 增强功能（Phase 1 后期）

- **F9 多语言** ⚠️ 部分：中文、英文识别已可用（依赖引擎支持），日文/韩文待验证。
- **F10 引擎自动路由** ❌ 未实现：当前仅支持用户指定和降级策略，字幕特征驱动路由待实现。
- **F11 进度展示** ❌ 未实现：CLI 中尚未显示处理进度与预计剩余时间。
- **F12 配置文件** ❌ 未实现：尚不支持 `sublift.toml` / `--config` 加载用户配置。
- **F13 引擎对照模式** ❌ 未实现：同一段视频用多个引擎并行识别，输出对比报告。

### 3.3 调试与可观察性工具（Phase 1 新增）

- **F14 帧裁剪检查** ✅：`sublift inspect` 导出采样帧和字幕区域裁剪图，含 manifest。
- **F15 时间轴检查** ✅：`sublift inspect-timeline` 检测字幕时间轴并导出代表性裁剪帧。
- **F16 信号分析** ✅：`sublift inspect-signals` 输出帧信号值和状态变化点，用于调参。
- **F17 文字框标注** ✅：`sublift inspect-boxes` 调用 Vision 检测文字候选框并可视化标注。
- **F18 引擎列表** ✅：`sublift list-engines` 列出所有可用的 OCR 引擎。

### 3.4 GUI 阶段功能（Phase 2 / 3）

- **F19 拖拽导入**：把视频文件拖入窗口即开始处理。
- **F20 实时预览**：左侧视频播放、右侧字幕时间轴同步高亮。
- **F21 字幕编辑**：识别后可手动修改文本、调整时间码、合并/拆分条目。
- **F22 字幕区域可视化框选**：用鼠标在画面上画出字幕所在矩形。
- **F23 批量处理队列**：一次拖入多个视频，串行处理。
- **F24 导出对话框**：选择格式与编码，保存到指定位置。
- **F25 引擎管理 UI**：在设置中查看/启用/禁用 OCR 引擎，配置默认路由策略。

## 4. 非功能需求

| 维度 | 要求 | 当前状态 |
|---|---|---|
| **性能** | 1080p 视频，1 fps 采样，处理速度 ≥ 1× 实时（在 M1 及以上） | ⚠️ 待 benchmark 验证 |
| **离线** | 默认流水线不依赖任何网络服务；云端 OCR 引擎仅作可选扩展 | ✅ 已满足 |
| **隐私** | 视频与识别文本默认在本地处理，不上传 | ✅ 已满足 |
| **资源占用** | 单视频处理峰值内存 ≤ 2 GB（1080p） | ⚠️ 待 benchmark 验证 |
| **可分发** | Phase 2 产物为单一 `.app`，无需用户安装运行时 | Phase 2 目标 |
| **可扩展** | OCR 引擎层支持第三方按接口实现并以插件形式加载 | ✅ 已满足 |
| **跨平台演进** | 算法核心代码与 OS / 厂商 API 解耦，平台特定能力收敛在适配层 | ⚠️ 部分满足（core.py 中有 Vision 耦合） |
| **当前兼容性** | macOS 13 (Ventura) 及以上，Apple Silicon 原生；Phase 3 扩展到 Windows / Linux | ✅ 已满足 |

## 5. 输入输出规范

### 输入

- 视频文件路径
- 可选配置：采样率、字幕区域、置信度阈值、OCR 引擎选择/路由策略、目标语言、合并间隔

### 输出

- 字幕文件（SRT / ASS / VTT）
- 处理日志（时间戳、识别文本、置信度、所用引擎）

## 6. 不在范围内（Non-Goals）

- ❌ 软字幕（已存在独立字幕轨）的提取——`ffmpeg` 已能胜任
- ❌ 实时直播流的字幕提取
- ❌ 字幕翻译（识别后的翻译交给其他工具）
- ❌ 云端 / SaaS 形态（仅作可选 OCR 引擎，非整体形态）

> 注：Windows / Linux 支持是长期目标（Phase 3），不在 MVP 范围内但架构必须为其留路。

## 7. 关键风险与权衡

| 风险 | 影响 | 缓解 | 状态 |
|---|---|---|---|
| 单一 OCR 引擎在某些字幕类型上精度不够 | 识别错误率高 | 多引擎可路由架构，按字幕特征选择；保留对照模式辅助用户判断 | ✅ 双引擎已集成 |
| 字幕区域不在画面下部（顶部、侧边） | F3 默认策略失效 | 提供手动指定区域参数 | ✅ 已支持 |
| 字幕半透明 / 动画进出 | 时间轴抖动 | F6 合并策略调参；GUI 阶段允许手动修正 | ⚠️ SSIM 验证有帮助，仍有待调优 |
| 平台特定 API 渗透到核心层 | Phase 3 跨平台代价高 | 严格分层，平台 API 只能出现在适配器实现中，核心仅依赖接口 | ⚠️ core.py 中有 Vision 耦合需清理 |
| Python → Swift 迁移成本 | 重写工作量 | 算法/参数在 Phase 1 充分验证；引擎接口在两端语义对齐 | Phase 2 问题 |

## 8. 验收标准

**Phase 1 (CLI MVP)**

- [x] 一条命令处理一个 1080p / 10 分钟 / 中文硬字幕视频，5 分钟内完成
- [x] 输出 SRT 文件可在主流播放器（IINA / VLC）中正常加载并对齐
- [x] 至少集成两种 OCR 引擎，可通过 CLI 参数切换
- [ ] 在清晰字幕样本上字符级准确率 ≥ 95%（待 benchmark 验证）

**Phase 2 (macOS GUI)**

- [ ] 应用通过公证（notarization），可分发给非开发者用户
- [ ] 从拖入视频到看到第一条识别结果 ≤ 10 秒（首帧反馈）
- [ ] 字幕条目可在 UI 中编辑并重新导出
- [ ] 支持在设置中切换默认 OCR 引擎

**Phase 3 (跨平台)**

- [ ] 同一份核心代码在 macOS / Windows / Linux 上行为一致
- [ ] 平台特定 OCR 引擎缺失时能优雅降级到通用引擎
