# SubLift 需求规格

## 1. 项目目标

为桌面用户提供一个**本地、离线、免费**的硬字幕提取工具，把烧录在视频画面中的字幕还原为可编辑的字幕文件。当前阶段聚焦 Apple Silicon Mac，长期目标是跨平台。

## 2. 用户与使用场景

| 用户类型 | 典型场景 |
|---|---|
| 字幕组 / 翻译者 | 二次校对、翻译已烧录字幕的影视片段 |
| 内容创作者 | 把旧素材中的硬字幕重新结构化，便于再剪辑 |
| 学习者 | 从带字幕的教程视频中导出文本，便于检索与笔记 |
| 开发者 / 技术用户 | 通过 CLI 批量处理视频文件 |

## 3. 功能需求

> 状态说明：❌ 未实现 · 🔧 Phase 1 范围 · ⚠️ 部分实现 · ✅ 已完成

### 3.1 必需功能（MVP / Phase 1）

- **F1 视频输入** 🔧：支持主流容器与编码（mp4 / mkv / mov，H.264 / H.265）。
- **F2 帧采样** 🔧：按可配置的采样率（默认 1 fps）从视频中抽取关键帧。
- **F3 字幕区域检测** 🔧：默认裁剪画面下部 30%，支持手动指定区域；Apple Vision 自适应定位。
- **F4 OCR 识别（多引擎可路由）** 🔧：通过统一接口调用 OCR 引擎，引擎可热插拔；Phase 1 集成 Apple Vision，返回文本 + 置信度。
- **F5 时间轴生成** 🔧：基于变化点检测状态机生成 `start_ms` / `end_ms`。
- **F6 去重与合并** 🔧：合并连续相同/相似的识别结果，消除抖动。
- **F7 字幕导出** 🔧：Phase 1 支持 SRT；ASS、VTT 留接口占位，后续补全。
- **F8 CLI** 🔧：`sublift extract <video> -o <output>`，支持参数覆盖默认配置，包括手动指定 OCR 引擎。

### 3.2 增强功能（Phase 1 后期及之后）

- **F9 多语言** ❌：中文、英文识别（依赖引擎支持），日文/韩文待验证。
- **F10 引擎自动路由** ❌：按字幕特征自动选择引擎。
- **F11 进度展示** ❌：CLI 中显示处理进度与预计剩余时间。
- **F12 配置文件** ❌：支持 `sublift.toml` / `--config` 加载用户配置。
- **F13 引擎对照模式** ❌：同一段视频用多个引擎并行识别，输出对比报告。
- **F14 PaddleOCR 第二引擎** ❌：集成 PaddleOCR 作为通用可选引擎。

### 3.3 调试与可观察性工具（Phase 1 后期）

- **F15 帧裁剪检查** ❌：`sublift inspect` 导出采样帧和字幕区域裁剪图，含 manifest。
- **F16 时间轴检查** ❌：`sublift inspect-timeline` 检测字幕时间轴并导出代表性裁剪帧。
- **F17 信号分析** ❌：`sublift inspect-signals` 输出帧信号值和状态变化点，用于调参。
- **F18 文字框标注** ❌：`sublift inspect-boxes` 调用 Vision 检测文字候选框并可视化标注。
- **F19 引擎列表** ❌：`sublift list-engines` 列出所有可用的 OCR 引擎。

### 3.4 GUI 阶段功能（Phase 2 / 3）

- **F20 拖拽导入**：把视频文件拖入窗口即开始处理。
- **F21 实时预览**：左侧视频播放、右侧字幕时间轴同步高亮。
- **F22 字幕编辑**：识别后可手动修改文本、调整时间码、合并/拆分条目。
- **F23 字幕区域可视化框选**：用鼠标在画面上画出字幕所在矩形。
- **F24 批量处理队列**：一次拖入多个视频，串行处理。
- **F25 导出对话框**：选择格式与编码，保存到指定位置。
- **F26 引擎管理 UI**：在设置中查看/启用/禁用 OCR 引擎，配置默认路由策略。

## 4. 非功能需求

| 维度 | 要求 | 当前状态 |
|---|---|---|
| **性能** | 1080p 视频，1 fps 采样，处理速度 ≥ 1× 实时（在 M1 及以上） | ❌ 待实现与 benchmark 验证 |
| **离线** | 默认流水线不依赖任何网络服务；云端 OCR 引擎仅作可选扩展 | 🔧 Phase 1 满足（本地 Vision） |
| **隐私** | 视频与识别文本默认在本地处理，不上传 | 🔧 Phase 1 满足 |
| **资源占用** | 单视频处理峰值内存 ≤ 2 GB（1080p） | ❌ 待实现与 benchmark 验证 |
| **可分发** | Phase 2 产物为单一 `.app`，无需用户安装运行时 | Phase 2 目标 |
| **可扩展** | OCR 引擎层支持第三方按接口实现并以插件形式加载 | 🔧 Phase 1 建立接口，后续完善插件机制 |
| **跨平台演进** | 算法核心代码与 OS / 厂商 API 解耦，平台特定能力收敛在适配层 | 🔧 Phase 1 严格分层，为 Phase 3 留路 |
| **当前兼容性** | macOS 13 (Ventura) 及以上，Apple Silicon 原生；Phase 3 扩展到 Windows / Linux | 🔧 Phase 1 满足 |

## 5. 输入输出规范

### 输入

- 视频文件路径
- 可选配置：采样率、字幕区域、置信度阈值、OCR 引擎选择/路由策略、目标语言、合并间隔

### 输出

- 字幕文件（SRT / ASS / VTT）
- 处理日志（时间戳、识别文本、置信度、所用引擎）

## 6. 不在范围内（Non-Goals）

- ❌ 软字幕（已存在独立字幕轨）的提取——`ffmpeg` 已能胜任
- ❌ 实时直播流的字幕提取
- ❌ 字幕翻译（识别后的翻译交给其他工具）
- ❌ 云端 / SaaS 形态（仅作可选 OCR 引擎，非整体形态）

> 注：Windows / Linux 支持是长期目标（Phase 3），不在 MVP 范围内但架构必须为其留路。

## 7. 关键风险与权衡

| 风险 | 影响 | 缓解 | 状态 |
|---|---|---|---|
| 单一 OCR 引擎在某些字幕类型上精度不够 | 识别错误率高 | 多引擎可路由架构，按字幕特征选择；保留对照模式辅助用户判断 | 🔧 Phase 1 单引擎（Vision），后续扩展 |
| 字幕区域不在画面下部（顶部、侧边） | F3 默认策略失效 | 提供手动指定区域参数 | 🔧 Phase 1 支持 |
| 字幕半透明 / 动画进出 | 时间轴抖动 | F6 合并策略调参；GUI 阶段允许手动修正 | 🔧 Phase 1 基础实现，后续调优 |
| 平台特定 API 渗透到核心层 | Phase 3 跨平台代价高 | 严格分层，平台 API 只能出现在适配器实现中，核心仅依赖接口 | 🔧 Phase 1 严格分层 |
| Python → Swift 迁移成本 | 重写工作量 | 算法/参数在 Phase 1 充分验证；引擎接口在两端语义对齐 | Phase 2 问题 |
| Apple Vision 在 CI 环境不可用 | 自动化测试受限 | ocr.vision 集成测试可手动；pipeline 闭环用 ocr.mock 验证 | 🔧 Phase 1 规划已考虑 |
| ffmpeg 系统依赖缺失 | 抽帧失败 | init.sh 检出并提示 | 🔧 Phase 1 规划已考虑 |

## 8. 验收标准

**Phase 1 (CLI MVP)**

- [ ] 一条命令处理一个 1080p / 10 分钟 / 中文硬字幕视频，5 分钟内完成
- [ ] 输出 SRT 文件可在主流播放器（IINA / VLC）中正常加载并对齐
- [ ] Phase 1 集成 Apple Vision OCR 引擎，CLI 可指定
- [ ] 在清晰字幕样本上字符级准确率 ≥ 95%（待 benchmark 验证）
- [ ] `uv run pytest` / `uv run ruff check .` / `uv run mypy src` 全绿
- [ ] `./init.sh` 完成环境检查与验证

**Phase 2 (macOS GUI)**

- [ ] 应用通过公证（notarization），可分发给非开发者用户
- [ ] 从拖入视频到看到第一条识别结果 ≤ 10 秒（首帧反馈）
- [ ] 字幕条目可在 UI 中编辑并重新导出
- [ ] 支持在设置中切换默认 OCR 引擎

**Phase 3 (跨平台)**

- [ ] 同一份核心代码在 macOS / Windows / Linux 上行为一致
- [ ] 平台特定 OCR 引擎缺失时能优雅降级到通用引擎
